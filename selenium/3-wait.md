## Неявные ожидания в Selenium

Неявное ожидание задаётся **один раз** для всего экземпляра драйвера и действует глобально на каждый вызов `find_element` / `find_elements`.

```python
driver.implicitly_wait(10)  # секунды
```

**Как работает:**
- При поиске элемента Selenium будет **повторять попытку** в течение заданного времени, пока элемент не появится в DOM (но **не проверяет** видимость, кликабельность или другие условия).
- Если элемент найден раньше — возвращает его сразу.
- Если по истечении таймаута элемент не найден — выбрасывает `NoSuchElementException`.

**Особенности:**
- Применяется **ко всем** операциям поиска (не к действиям, таким как `.click()` или `.send_keys()`).
- Устанавливается **глобально** и не может быть переопределено для отдельных элементов.
- Смешивание с явными ожиданиями (`WebDriverWait`) может приводить к **непредсказуемому поведению** (например, суммарное время ожидания становится больше, чем ожидалось).

---

## Явные ожидания в Selenium: WebDriverWait + expected_conditions

В Selenium **явное ожидание (Explicit Wait)** — это механизм, который приостанавливает выполнение скрипта до наступления **конкретного условия** для элемента. Реализуется через класс `WebDriverWait` в связке с модулем `expected_conditions`.

```python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.common.by import By

# Ждём до 10 секунд, пока элемент не станет кликабельным
element = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.ID, "submit"))
)
```

**Особенности:**
- WebDriver по умолчанию опрашивает условие каждые **500 мс**.
- Доступен широкий набор встроенных условий: `visibility_of_element_located`, `presence_of_element_located`, `element_to_be_clickable`, `alert_is_present` и др..
- Можно создавать **пользовательские условия**.
- Даёт **точный контроль**: ожидание только под конкретный элемент и условие.

---

## Сравнение ожиданий в Selenium

| Тип ожидания | Где задаётся | На что влияет | Гибкость |
|--------------|--------------|---------------|----------|
| **Неявное** (`implicitly_wait`) | Один раз на драйвер | Только поиск элементов (`find_element`) | Низкая — единые настройки для всех |
| **Явное** (`WebDriverWait`) | Индивидуально для каждого условия | Конкретное условие для конкретного элемента | Высокая — выбор условия, таймаута, частоты опроса |

**Пример совместного использования (не рекомендуется):**
```python
driver.implicitly_wait(5)  # глобально
# явное ожидание с таймаутом 10 секунд
element = WebDriverWait(driver, 10).until(EC.visibility_of_element_located((By.ID, "id")))
# Реальное время ожидания может достигать 5 + 10 секунд
```

## Playwright: авто-ожидания (auto-waiting)

В Playwright **нет** явных и неявных ожиданий в том виде, как в Selenium. Вместо этого каждый метод взаимодействия с элементом (`.click()`, `.fill()` и др.) **автоматически** ждёт, пока элемент не станет **действительно готовым к действию**.

```python
# Playwright — никаких явных wait! Всё автоматически
page.locator("#submit").click()  # ждёт, пока элемент станет видимым, стабильным и кликабельным
```

**Playwright проверяет перед действием:**
- элемент **видим**;
- элемент **стабилен** (не анимируется);
- элемент **получает события** (не перекрыт другими элементами);
- элемент **включён (enabled)**.

---

## Ключевые отличия

| Аспект | Selenium (явные ожидания) | Playwright (авто-ожидания) |
|--------|---------------------------|----------------------------|
| **Подход** | Ручное управление — разработчик **сам** пишет `WebDriverWait` для каждого действия | Встроено в API — каждый метод **автоматически** ждёт готовности элемента |
| **Код** | Много **шаблонного кода** (импорты, `until`, `EC`) | Минималистичный — одна строка без дополнительных ожиданий |
| **Где логика** | Логика ожидания **вне** действия (отдельный вызов `wait.until()`) | Логика ожидания **внутри** действия (метод сам решает, когда можно выполниться) |
| **Условия** | Явно указываются через `expected_conditions` | Неявные, основаны на **actionability checks** (видимость, стабильность, enabled) |
| **Flakiness** | Высокий риск **нестабильности** при неправильной настройке ожиданий | Значительно **меньше flakiness** благодаря умной автоматике |

---

## Итог

> **Selenium** требует от разработчика **явно управлять ожиданиями** через `WebDriverWait` + `expected_conditions`. Это даёт гибкость, но порождает много шаблонного кода и является частым источником нестабильности тестов.

> **Playwright** идёт другим путём — **авто-ожидания встроены прямо в API**. Вместо того чтобы заставлять тестировщика угадывать тайминги, Playwright сам проверяет, готов ли элемент к действию. Это радикально сокращает количество кода и снижает flakiness.

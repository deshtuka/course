# Тема 7. Принцип «Абстракция».


### 1. Введение

Мы прошли три столпа ООП: инкапсуляцию (скрываем детали), наследование (переиспользуем код) и полиморфизм (один интерфейс — много реализаций). Остался четвёртый, самый важный для проектирования — **абстракция**.

**Абстракция** — это выделение существенных характеристик объекта и игнорирование несущественных. В программировании это означает создание **интерфейса** (набора методов), который описывает, *что* должен уметь делать объект, но не говорит, *как* он это делает.

Зачем это нужно? Представьте, что вы проектируете систему управления транспортом. Вы знаете, что у любого транспортного средства есть метод `move()`. Но как именно движется автомобиль, велосипед или самолёт — это детали реализации, которые вас не волнуют на этапе проектирования. Вы просто описываете **контракт**: «любое транспортное средство обязано уметь двигаться».

В Python абстракция реализуется с помощью **абстрактных классов** и **абстрактных методов**. Это не просто соглашение (как с `_`), а **принудительное** требование: если класс наследуется от абстрактного, он **обязан** реализовать все абстрактные методы, иначе его нельзя будет создать.

---

### 2. Проблематика

Вернёмся к нашему классу `Animal` из предыдущих модулей. У него был метод `make_sound()`, который мы переопределяли в наследниках. Но что, если мы создадим объект `Animal` напрямую? Какой звук он должен издавать? Никакой, потому что `Animal` — это обобщение, абстрактное понятие, а не конкретное животное.

```python
class Animal:
    def make_sound(self):
        print("???") # неопределённость

# Мы можем создать объект абстрактного животного
unknown_animal = Animal()
unknown_animal.make_sound()  # ???
```

Это нелогично: мы не должны создавать экземпляры классов, которые не имеют конкретной реализации. Абстрактный класс — это **шаблон** для других классов, а не для объектов.

**Решение:** сделать `Animal` абстрактным классом, а метод `make_sound` — абстрактным методом. Тогда:
- Создать объект `Animal()` станет невозможно.
- Любой наследник **обязан** реализовать `make_sound()`, иначе он тоже станет абстрактным и его нельзя будет создать.

### 3. Абстрактные классы и методы

Для работы с абстракцией в Python используется модуль `abc` (Abstract Base Classes). В нём есть:
- `ABC` — базовый класс для создания абстрактных классов.
- `@abstractmethod` — декоратор для объявления абстрактных методов.

#### 3.1. Создание абстрактного класса

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def make_sound(self):
        pass

    @abstractmethod
    def move(self):
        pass
```

Теперь `Animal` — абстрактный класс. У него есть два абстрактных метода: `make_sound()` и `move()`. Мы не можем создать объект этого класса:

```python
animal = Animal()  # Будет исключение -> TypeError: Can't instantiate abstract class Animal with abstract methods make_sound, move
```

#### 3.2. Наследование от абстрактного класса

Дочерний класс **обязан** реализовать все абстрактные методы родителя. Если он реализует не все, он тоже становится абстрактным.

```python
class Dog(Animal):
    def make_sound(self):
        print("Гав!")

    def move(self):
        print("Собака бегает")
```

Теперь `Dog` — конкретный класс, его можно создавать:

```python
rex = Dog()
rex.make_sound()  # Гав!
rex.move()        # Собака бегает
```

Если бы мы забыли реализовать `move()`:

```python
class Cat(Animal):
    def make_sound(self):
        print("Мяу!")
    # move не реализован

cat = Cat()  # Будет исключение -> TypeError: Can't instantiate abstract class Cat with abstract method move
```

Это защищает нас от ошибок: мы не сможем создать объект, у которого нет полноценной реализации всех методов.

### 4. Абстрактные методы с реализацией

Иногда полезно дать частичную реализацию в абстрактном классе, а дочерние классы будут её расширять. В Python абстрактный метод может иметь тело:

```python
class Animal(ABC):
    @abstractmethod
    def make_sound(self):
        print("Животное издаёт звук")  # общая логика

class Dog(Animal):
    def make_sound(self):
        super().make_sound()  # вызываем родительскую реализацию
        print("...и лает!")

rex = Dog()
rex.make_sound()
# Вывод:
# Животное издаёт звук
# ...и лает!
```

Однако, если метод абстрактный, дочерние классы **всё равно обязаны его переопределить** (даже если в родителе есть тело). Это требование языка: абстрактный метод должен быть переопределён, иначе класс остаётся абстрактным.

---

### 5. Абстракция и интерфейсы

Интерфейсы реализуются через абстрактные классы без атрибутов и с абстрактными методами. По сути, абстрактный класс с одними абстрактными методами — это и есть интерфейс.

```python
class Drawable(ABC):
    @abstractmethod
    def draw(self):
        pass

class Circle(Drawable):
    def draw(self):
        print("Рисуем круг")

class Square(Drawable):
    def draw(self):
        print("Рисуем квадрат")
```

Теперь любая функция может принимать `Drawable` и быть уверенной, что у объекта есть метод `draw()`.

### Распространенные ошибки

| Ошибка                                                | Пояснение                                                                                                              | Решение                                                                          |
|-------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------|
| Забывают импортировать `ABC` и `abstractmethod`       | Без импорта декоратор не сработает, и класс не станет абстрактным.                                                     | Добавьте `from abc import ABC, abstractmethod`.                                  |
| Создают объект абстрактного класса                    | Это вызовет ошибку `TypeError`.                                                                                        | Убедитесь, что все абстрактные методы реализованы в наследнике.                  |
| Реализуют не все абстрактные методы в дочернем классе | Если пропустить хотя бы один, класс останется абстрактным, и его нельзя создать.                                       | Проверьте, что все методы переопределены.                                        |
| Используют абстрактные методы для всего подряд        | Не все методы должны быть абстрактными. Абстрактными делают только те, которые обязательно должны быть переопределены. | Оставляйте обычные методы, если в них есть общая логика.                         |
| Путают абстракцию с инкапсуляцией                     | Абстракция — это про *контракт* (что должен уметь объект), а инкапсуляция — про *скрытие данных*.                      | Помните: абстракция отвечает на вопрос «Что?», инкапсуляция — «Как это скрыто?». |

---

### Краткий итог

- **Абстракция** — это выделение общего интерфейса и сокрытие деталей реализации.
- Абстракция реализуется через модуль `abc`:
  - `ABC` — базовый класс.
  - `@abstractmethod` — декоратор для абстрактных методов.
- Абстрактный класс нельзя создать, он служит только для наследования.
- Дочерний класс **обязан** реализовать все абстрактные методы, иначе он тоже становится абстрактным.
- Абстракция помогает проектировать надёжные, расширяемые системы с чёткими контрактами между компонентами.

# Тема 5. Принцип «Наследование».

### 1. Введение

До этого времени мы создавали отдельные классы для разных сущностей: `Animal`, `Cat`, `Dog`, `BankAccount`... Но что, если эти классы имеют много общего? Например, и кошка, и собака — это животные. У всех животных есть имя, возраст, они умеют есть и спать. Если мы напишем два класса `Cat` и `Dog` с одинаковыми атрибутами и методами.

**Проблема:**
```python
class Cat:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f"{self.name} ест")

    def sleep(self):
        print(f"{self.name} спит")


class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f"{self.name} ест")

    def sleep(self):
        print(f"{self.name} спит")
```

Код дублируется. Если нам нужно добавить новый атрибут (например, `weight`), придётся менять оба класса. Это неудобно и чревато ошибками.

**Решение:** создать **общий родительский класс** (суперкласс, базовый класс) `Animal`, в котором описать общие свойства и поведение, а затем **наследовать** от него классы `Cat` и `Dog`. Они автоматически получат всё, что есть у родителя, и при этом смогут добавить или переопределить что-то своё.

Это и есть **наследование** — механизм, позволяющий строить иерархию классов, переиспользовать код и расширять функциональность.

---

### 2. Базовый синтаксис наследования

Чтобы создать класс-наследник, указываем имя родительского класса в скобках после имени дочернего:

```python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f"{self.name} ест")

    def sleep(self):
        print(f"{self.name} спит")

class Cat(Animal):
    # Дочерний класс, пока пустой, но уже имеет все методы родителя
    pass
```

Теперь создадим объекты и вызовем методы:

```python
barsik = Cat("Барсик", 3)

barsik.eat()   # Барсик ест
print(barsik.name)  # Барсик
```

Мы не писали `__init__`, `eat`, `sleep` в дочерних классах, но они унаследовали их от `Animal`. Это называется **наследованием реализации**.

Данный пример показывает тип **одиночного наследования**

### 3. Типы наследования:

- Одиночное наследование (Single Inheritance)
- Множественное наследование (Multiple Inheritance)
- Многоуровневое наследование (Multilevel Inheritance)
- Иерархическое наследование (Hierarchical Inheritance)
- Гибридное наследование (Hybrid Inheritance)
- Миксины (Mixin)

---

### 3.1. Одиночное наследование (Single Inheritance)

Самый простой и частый случай. Класс-ребенок наследуется от **одного** класса-родителя.

```python
class Animal:
    def __init__(self, name):
        self.name = name
    
    def breathe(self):
        return f"{self.name} дышит воздухом"

class Dog(Animal):  # Dog наследуется ТОЛЬКО от Animal
    def bark(self):
        return f"{self.name} говорит Гав!"

# Проверка
rex = Dog("Рекс")
print(rex.breathe())  # Рекс дышит воздухом (унаследовано)
print(rex.bark())     # Рекс говорит Гав! (свое)
```

**Когда использовать:** Когда у вас четкая иерархия — `Animal` → `Dog`.

---

## 3.2. Множественное наследование (Multiple Inheritance)
Класс-ребенок наследуется сразу от **двух и более** родителей.

```python
class Animal:
    def eat(self):
        return "Кушаю"

class Flyable:
    def move(self):
        return "Лечу по воздуху"

class Swimmable:
    def move(self):
        return "Плыву по воде"

class Duck(Animal, Flyable, Swimmable):  # Утка наследник ТРЕХ классов!
    pass

# Проверка
duck = Duck()
print(duck.eat())      # Кушаю (от Animal)
print(duck.move())     # Лечу по воздуху (от Flyable)
```

**Важнейший нюанс (MRO):**
Если у двух родителей одинаковый метод (`move`), Python будет искать его **слева направо**. В классе `Duck(Animal, Flyable, Swimmable)` — вызовется `move()` из **Flyable**, потому что он левее.

---

## 3.3. Многоуровневое наследование (Multilevel Inheritance)
Это когда вы строите **цепочку**: ребенок → родитель → дедушка. 

```python
class Animal:
    def live(self):
        return "Живу"

class Mammal(Animal):      # Mammal наследник Animal
    def feed_milk(self):
        return "Кормлю молоком"

class Whale(Mammal):       # Whale наследник Mammal (а значит и Animal)
    def swim(self):
        return "Плаваю в океане"

# Проверка
whale = Whale()
print(whale.live())       # Живу (от Animal)
print(whale.feed_milk())  # Кормлю молоком (от Mammal)
print(whale.swim())       # Плаваю в океане (свое)
```

**Когда использовать:** Для строгих уровней (Царство → Тип → Класс → Отряд).

---

## 3.4. Иерархическое наследование (Hierarchical Inheritance)
Это не отдельный синтаксис, а **идея**: один родитель и много детей. В Python это просто несколько классов от одного предка.

```python
class Animal:
    def eat(self):
        return "Ем"

class Cat(Animal):   # Кошка наследник Animal
    def meow(self):
        return "Мяу"

class Dog(Animal):   # Собака наследник Animal
    def bark(self):
        return "Гав"

class Cow(Animal):   # Корова наследник Animal
    def moo(self):
        return "Му"
```

Все трое умеют `eat()`, но каждый делает свое.

**Когда использовать:** Когда у вас общий интерфейс для разных типов (например, все животные едят, но звуки разные).

---

## 3.5. Гибридное наследование (Hybrid Inheritance)
Это **комбинация** множественного и многоуровневого. Самый сложный случай. Классический "ромб":

```python
class Animal:
    def say(self):
        return "Звук животного"

class Mammal(Animal):
    def say(self):
        return "Млекопитающее мычит"

class Bird(Animal):
    def say(self):
        return "Птица чирикает"

class Bat(Mammal, Bird):  # Летучая мышь — и млекопитающее, и птица? (Нет, но для примера)
    pass

# Что вызовется?
bat = Bat()
print(bat.say())  # Млекопитающее мычит (берется слева направо)
```

**Важно:** C3-линеаризация (алгоритм, который строит четкий порядок вызовов). Python сам решает, чей метод взять, строго по правилам.

---

## 3.6. Миксины (Mixin)
В Python часто используют множественное наследование не для "является" (is-a), а для "умеет" (can-do). Такие маленькие классы-примеси называются **Mixin**.

```python
class FlyMixin:
    def fly(self):
        return "Я лечу!"

class SwimMixin:
    def swim(self):
        return "Я плыву!"

class Duck(Animal, FlyMixin, SwimMixin):
    pass

# Утка умеет и летать, и плавать, при этом она животное
```

### 4. Функция `super()` и расширение функциональности: 

Часто нам нужно не просто заменить родительский метод, а **добавить** к его логике что-то своё. Например, у кошки кроме имени и возраста есть ещё цвет шерсти. Мы хотим добавить атрибут `color`, но не хотим заново писать код для `name` и `age`. Для этого в конструкторе дочернего класса вызываем конструктор родителя через **`super()`**:

```python
class Cat(Animal):
    def __init__(self, name, age, color):
        super().__init__(name, age)   # вызываем конструктор родителя
        self.color = color            # добавляем свой атрибут
```

**Важно!** В методе `super()` мы обязаны передать ровно те атрибуты, которые принимает конструктор `__init__` родительского класса (Animal) 

`super()` возвращает объект-прокси, через который можно обращаться к методам родительского класса. В данном случае мы вызвали `__init__` родителя, чтобы инициализировать `name` и `age`, а затем добавили `color`.

Теперь создаём кошку:

```python
barsik = Cat("Барсик", 3, "рыжий")
print(barsik.name)   # Барсик
print(barsik.color)  # рыжий
```

Точно так же можно расширить другие методы:

```python
class Cat(Animal):
    def make_sound(self):
        super().make_sound()   # вызов метода родителя (если есть)
        print("Мяу!")          # добавляем своё
```

Но в родителе `Animal` нет `make_sound`, поэтому лучше просто переопределить.

### 5. MRO — порядок разрешения методов

Что произойдёт, если мы вызовем метод, который определён и в родителе, и в дочернем? Python ищет метод в **иерархии классов** в определённом порядке. Этот порядок называется **MRO (Method Resolution Order)**.

Для класса `Cat` MRO выглядит так: `Cat` -> `Animal` -> `object` (встроенный базовый класс). Python проверяет класс объекта, затем его родителя, затем родителя родителя и так далее, пока не найдёт метод или не дойдёт до `object` (если метод не найден, возникает ошибка).

Можно посмотреть MRO для класса:

```python
print(Cat.__mro__)
# (<class '__main__.Cat'>, <class '__main__.Animal'>, <class 'object'>)
```

Если у класса несколько родителей (множественное наследование), MRO становится сложнее, но Python использует алгоритм C3-линеаризации, который гарантирует предсказуемый порядок. Пока достаточно знать, что поиск идёт слева направо и в глубину.

**Пример множественного наследования (кратко):**

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
print(D.__mro__)   # D -> B -> C -> A -> object
```

Важно знать, что `super()` будет следовать MRO, а не просто вызывать родителя напрямую.

### 6. Функция `super()` в контексте MRO

Когда мы вызываем `super()` в дочернем классе, Python выбирает следующий класс в MRO. Это особенно важно при множественном наследовании, чтобы избежать пропуска родительских методов (проблема «алмаза»). В одиночном наследовании `super()` просто вызывает метод родителя.

Рассмотрим пример с конструкторами:

```python
class Animal:
    def __init__(self, name):
        print("Animal init")
        self.name = name

class Mammal(Animal):
    def __init__(self, name, fur_color):
        print("Mammal init")
        super().__init__(name)
        self.fur_color = fur_color

class Cat(Mammal):
    def __init__(self, name, fur_color, breed):
        print("Cat init")
        super().__init__(name, fur_color)
        self.breed = breed

c = Cat("Барсик", "рыжий", "сиамский")
```

Вывод:
```
Cat init
Mammal init
Animal init
```

`super()` последовательно вызывает конструкторы по цепочке MRO.

### 7. Полезные возможности наследования

- **Наследование атрибутов класса:** дочерний класс видит атрибуты класса родителя, если не переопределяет их.
- **Расширение методов:** с помощью `super()` можно добавить логику до или после вызова родительского метода.
- **Полиморфизм** (будет далее) — возможность работать с объектами разных классов через единый интерфейс, обеспечивается наследованием.

### Распространенные ошибки

| Ошибка                                                  | Пояснение                                                                                                             | Решение                                                                                                        |
|---------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------|
| Забывают вызвать `super().__init__()` в дочернем классе | Тогда атрибуты родителя не инициализируются, и объект может быть не полностью создан.                                 | Всегда вызывайте `super().__init__(...)` в конструкторе дочернего класса, если родительский конструктор нужен. |
| Путают порядок аргументов при вызове `super()`          | Аргументы должны соответствовать параметрам родительского конструктора.                                               | Проверьте сигнатуру родительского метода.                                                                      |
| Пытаются переопределить метод, но забывают `self`       | Метод должен иметь `self` первым параметром.                                                                          | Добавьте `self`.                                                                                               |
| Используют имя класса вместо `super()`                  | Например, `Animal.__init__(self, name)` — это работает, но при множественном наследовании может привести к проблемам. | Используйте `super()` для гибкости и поддержки MRO.                                                            |
| Не понимают, зачем нужно наследование, и дублируют код  | Создают отдельные классы без общего родителя.                                                                         | Выделите общую часть в базовый класс.                                                                          |

---

### Краткий итог

- **Наследование** позволяет создавать новые классы на основе существующих, переиспользуя их код.
- Синтаксис: `class Child(Parent):`
- Дочерний класс наследует все атрибуты и методы родителя, может переопределять их или добавлять новые.
- Для вызова методов родителя используется **`super()`**.
- **MRO** — порядок поиска методов, который можно посмотреть через `ClassName.__mro__`.
- Наследование помогает строить иерархии, уменьшать дублирование и облегчать расширение.

### Шпаргалка
| Тип                | Синтаксис                | Описание                   | Пример                                 |
|--------------------|--------------------------|----------------------------|----------------------------------------|
| **Одиночное**      | `class B(A)`             | Один родитель              | Собака → Животное                      |
| **Множественное**  | `class B(A, C)`          | Несколько родителей        | Утка → (Животное, Летающее, Плавающее) |
| **Многоуровневое** | `class C(B): class B(A)` | Цепочка                    | Кит → Млекопитающее → Животное         |
| **Иерархическое**  | `class B(A): class C(A)` | Один родитель, много детей | Кошка, Собака, Корова → Животное       |

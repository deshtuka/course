# Тема 4. Принцип «Инкапсуляция».

### 1. Введение

В прошлых модулях мы научились создавать классы, объекты, добавлять им атрибуты и методы. Но пока все атрибуты были **публичными** — мы могли напрямую обратиться к ним извне и изменить как угодно:

```python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age = age

simba = Animal("Симба", 5)
simba.age = -10   # Никто не запрещает!
print(simba.age)  # -10 — это не правильно
```

А что, если возраст не может быть отрицательным? Или у нас есть правило, что при изменении возраста нужно обновить какой-то другой атрибут (например, категорию «маленький/взрослый»)? Если разрешить прямой доступ, мы теряем контроль над данными.

**Инкапсуляция** — это принцип, который:
1. **Объединяет** данные (атрибуты) и методы (поведение) внутри одного объекта (это мы уже делаем).
2. **Скрывает** внутреннее состояние объекта от прямого доступа извне, предоставляя только контролируемый интерфейс для работы с ними.

В Python нет строгой приватности, как в Java или C++, но есть **соглашения** и механизмы, которые помогают разработчику указать, что данное поле не предназначено для внешнего использования. Мы рассмотрим их по порядку.

---

### 2. Правила доступа

#### 2.1. Публичные атрибуты (public)
По умолчанию все атрибуты и методы — публичные. К ним можно обращаться откуда угодно. Мы уже использовали их.

#### 2.2. Защищённые атрибуты (protected) — с одним подчёркиванием `_`
Если имя атрибута начинается с одного подчёркивания (например, `_age`), это сигнал для разработчиков: «Это внутренний атрибут, не трогайте его без необходимости». Но технически доступ к нему всё равно есть.

```python
class Animal:
    def __init__(self, name, age):
        self.name = name    # публичный атрибут
        self._age = age     # защищённый атрибут

simba = Animal("Симба", 5)
print(simba._age)   # 5 — работает, но так делать не рекомендуется
```

Это просто договорённость, интерпретатор не препятствует доступу. Используется для обозначения «внутренних» полей, которые могут изменяться в будущих версиях класса.

#### 2.3. Приватные атрибуты (private) — с двумя подчёркиваниями `__`

Если имя начинается с двух подчёркиваний и не заканчивается двумя подчёркиваниями (иначе это магический метод), Python выполняет **искажение имени (name mangling)**. Имя преобразуется в `_ClassName__attribute`. Это делает его труднодоступным извне.

```python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.__age = age   # приватный атрибут

simba = Animal("Симба", 5)
print(simba.__age)  # AttributeError: 'Animal' object has no attribute '__age'
```

**Зачем нужны правила доступа?**  
Чтобы предотвратить случайное переопределение атрибутов в дочерних классах (это тема наследования). Для обычной защиты данных это не панацея, но сигнал: «Не лезь».

---

### 3. Геттеры и сеттеры — контролируем доступ

Если мы хотим запретить прямой доступ к атрибуту, но предоставить возможность читать и изменять его значение с проверками, мы создаём **методы-аксессоры**:

- **Геттер (getter)** — возвращает значение атрибута.
- **Сеттер (setter)** — устанавливает новое значение, выполняя валидацию.

Пример с возрастом:

```python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.__age = age   # приватный атрибут

    def get_age(self):
        """Геттер для возраста"""
        return self.__age

    def set_age(self, new_age):
        """Сеттер с проверкой"""
        if new_age < 0:
            raise ValueError("Возраст не может быть отрицательным!")
        self.__age = new_age
```

Теперь доступ к возрасту осуществляется только через методы:

```python
simba = Animal("Симба", 5)
print(simba.get_age())   # 5
simba.set_age(6)         # ок
simba.set_age(-10)       # ValueError
```

Плюсы:
- Мы можем добавить любую логику (валидация, логирование, обновление других полей).
- Если в будущем изменится способ хранения возраста (например, будем хранить дату рождения), мы поменяем только методы, а внешний код не пострадает.

Минусы:
- Код становится более громоздким, вместо простого `obj.age` приходится писать `obj.get_age()`.

---

### 4. Свойства (property) — элегантный синтаксис

Python предлагает декоратор `@property`, который позволяет обращаться к геттеру как к обычному атрибуту, а сеттер оформляется через `@имя.setter`. Это делает интерфейс чистым и удобным.

> Декоратор - это функция обертка над основной функцией, цель которой добавить новый функционал поверх основного, не исказив его. Пример: таймер выполнения функции

Перепишем класс с использованием `property`:

```python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.__age = age

    @property
    def age(self):
        """Геттер для возраста"""
        return self.__age

    @age.setter
    def age(self, new_age):
        """Сеттер с проверкой"""
        if new_age < 0:
            raise ValueError("Возраст не может быть отрицательным!")
        self.__age = new_age
```

Теперь мы можем работать с возрастом как с обычным атрибутом, но при присваивании выполняется проверка:

```python
simba = Animal("Симба", 5)
print(simba.age)   # 5 (вызов геттера)
simba.age = 6      # вызов сеттера
simba.age = -10    # ValueError
```

**Важно:** `@property` позволяет определить также **геттер без сеттера** (только для чтения). Если сеттер не определён, то присваивание вызовет ошибку.

---

### 5. Зачем всё это?

На начальном этапе многие не видят смысла в инкапсуляции: «Зачем писать геттеры и сеттеры, если можно просто обратиться к полю?». Ответы:

1. **Контроль целостности данных.** Вы не позволите установить некорректное значение (отрицательный возраст, пустую строку для имени и т.д.).
2. **Гибкость изменений.** Если вы решите изменить внутреннее представление (например, возраст хранить в месяцах), то внешний код не сломается — вы просто поменяете геттер/сеттер, а остальные продолжат использовать `obj.age`.
3. **Сокрытие реализации.** Пользователь класса видит только интерфейс (методы и свойства), а внутренняя сложность скрыта. Это уменьшает когнитивную нагрузку.

### Распространенные ошибки

| Ошибка                                                               | Пояснение                                                                 | Решение                                                                                                      |
|----------------------------------------------------------------------|---------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| Используют `__` для всех атрибутов без необходимости                 | Это усложняет отладку и тестирование, особенно для новичков               | Используйте `_` для защиты, а `__` только когда действительно нужно избежать конфликтов в наследниках        |
| Забывают определить сеттер, но пытаются присвоить значение свойству  | Если есть `@property` без `@setter`, то `obj.attr = value` вызовет ошибку | Либо сделайте атрибут только для чтения, либо добавьте сеттер                                                |
| Пытаются обратиться к приватному атрибуту через `_ClassName__attr`   | Это противоречит идее инкапсуляции, хоть и технически возможно            | Не делайте так, это считается плохой практикой                                                               |
| Пишут геттеры и сеттеры для каждого атрибута, даже если они не нужны | Избыточный код усложняет проект                                           | Начинайте с публичных атрибутов, а когда появится реальная потребность в контроле, рефакторьте с `@property` |
| Не используют `@property` и остаются с методами `get_...`/`set_...`  | Это рабочий вариант, но менее удобный                                     | Используйте `@property` для более чистого интерфейса                                                         |

---

### Краткий итог

- **Инкапсуляция** — это сокрытие внутреннего состояния и предоставление контролируемого интерфейса.
- В Python нет строгой приватности, но есть правила:
  - `_` — защищённый (не трогать без нужды).
  - `__` — приватный (не доступен из вне).
- Для управления доступом используют **геттеры и сеттеры**, а лучше — декоратор `@property`, который позволяет сохранить синтаксис атрибута.
- Инкапсуляция даёт контроль над данными, упрощает поддержку и уменьшает связанность кода.

# Тема 6. Принцип «Полиморфизм».

### 1. Введение

В прошлом модуле мы научились строить иерархии классов с помощью наследования. Дочерние классы наследуют методы родителей и могут переопределять их, чтобы добавить специфичное поведение. Но зачем нам вообще переопределять методы? Чтобы добиться **полиморфизма** — одного из ключевых принципов ООП.

**Полиморфизм** (от греческого «много форм») — это способность объектов разных классов реагировать на один и тот же вызов метода по-своему, при этом для внешнего кода вызов выглядит одинаково.

Представьте, что у вас есть зоопарк. Вы хотите, чтобы все животные издавали звук. Вы не хотите знать, кто именно перед вами — кошка, собака или корова. Вы просто говорите: «Издай звук!», и каждое животное делает это по-своему. Это и есть полиморфизм.

В Python полиморфизм проявляется не только через наследование, но и через **утиную типизацию** (duck typing): если объект имеет нужный метод, он может быть использован, независимо от его типа.

---

### 2. Полиморфизм через наследование и переопределение

Начнём с классического примера с наследованием. У нас есть базовый класс `Animal` с методом `make_sound()`. Но мы не знаем, какой звук издаёт абстрактное животное, поэтому метод может быть пустым или выбрасывать исключение. В дочерних классах мы переопределяем его.

```python
class Animal:
    def make_sound(self):
        pass

class Dog(Animal):
    def make_sound(self):
        print("Гав!")

class Cat(Animal):
    def make_sound(self):
        print("Мяу!")

class Cow(Animal):
    def make_sound(self):
        print("Муу!")
```

Теперь мы можем создать список разных животных и вызывать у всех один и тот же метод:

```python
animals = [Dog(), Cat(), Cow()]
for animal in animals:
    animal.make_sound()
```

Вывод:
```
Гав!
Мяу!
Муу!
```

**Что произошло?**  
Мы использовали **полиморфный вызов** — один и тот же код `animal.make_sound()` работает по-разному в зависимости от реального типа объекта. При этом внешний код не знает, какой именно объект обрабатывает, — это решается во время выполнения (динамический полиморфизм).

---

### 3. Полиморфизм в функциях и методах

Полиморфизм особенно полезен, когда мы пишем функции, которые принимают объекты разных типов, но с единым интерфейсом.

Пример: функция `make_animal_speak(animal)`, которая заставляет любое животное говорить.

```python
def make_animal_speak(animal):
    animal.make_sound()

# Вызываем с разными объектами
make_animal_speak(Dog())   # Гав!
make_animal_speak(Cat())   # Мяу!
```

Функция работает с любым объектом, у которого есть метод `make_sound()`. Это и есть полиморфизм в действии.

---

### 4. Утиная типизация (duck typing)

В Python мы не обязаны создавать иерархию наследования, чтобы использовать полиморфизм. Достаточно того, что у объекта есть нужный метод. Это называется **утиной типизацией** по принципу: «Если это ходит как утка и крякает как утка, то это утка».

Рассмотрим пример с разными классами, которые не связаны наследованием, но у всех есть метод `play()`.

```python
class Guitar:
    def play(self):
        print("Струны звенят...")

class Piano:
    def play(self):
        print("Клавиши звучат...")

class Drums:
    def play(self):
        print("Барабаны гремят!")
```

Функция для воспроизведения:

```python
def perform(instrument):
    instrument.play()

perform(Guitar())   # Струны звенят...
perform(Piano())    # Клавиши звучат...
perform(Drums())    # Барабаны гремят!
```

Несмотря на то, что классы не имеют общего предка, они полиморфны благодаря наличию метода `play()`. Это делает язык программирования очень гибким и позволяет легко расширять систему без изменения существующего кода.

---

### 5. Полиморфизм со встроенными типами

Широко используется полиморфизм со встроенными типами. Например, оператор `+` ведёт себя по-разному для чисел и строк:

```python
print(5 + 3)       # 8 (сложение)
print("Hello " + "world")  # Hello world (конкатенация)
```

А функция `len()` работает со строками, списками, словарями и даже пользовательскими объектами, если определён метод `__len__()`.

```python
class Book:
    def __init__(self, pages):
        self.pages = pages
    def __len__(self):
        return self.pages

book = Book(300)
print(len(book))   # 300
```

Это пример полиморфизма на уровне специальных методов.

---

### 6. Зачем нужен полиморфизм?

- **Упрощение кода.** Вы пишете общую логику, не заботясь о конкретных типах.
- **Расширяемость.** Можно добавлять новые классы, реализующие тот же интерфейс, без изменения существующих функций.
- **Гибкость.** В Python утиная типизация позволяет использовать классы, даже если они не унаследованы от общего предка.
- **Читаемость.** Код становится более абстрактным и понятным: «сделай что-то» вместо «если это кошка, сделай так, если собака — иначе».

### Распространенные ошибки

| Ошибка                                                              | Пояснение                                                                                                    | Решение                                                                                                                    |
|---------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------|
| Используют `isinstance()` для проверки типа перед вызовом метода    | Это нарушает полиморфизм и делает код жёстким. Если вы полагаетесь на наличие метода, проверка типа излишня. | Просто вызывайте метод, полагаясь на утиную типизацию. Используйте `hasattr()` только если нужно проверить наличие метода. |
| Переопределяют метод, но меняют его сигнатуру (добавляют параметры) | При полиморфном вызове метод должен принимать одинаковые аргументы, иначе код сломается.                     | Сохраняйте одинаковую сигнатуру, либо используйте `*args, **kwargs` для гибкости.                                          |
| Забывают вызвать `super()` при переопределении                      | Если в родителе метод делает что-то важное, его пропуск может привести к ошибкам.                            | Если нужно расширить поведение, используйте `super()`.                                                                     |
| Думают, что полиморфизм возможен только при наследовании            | В Python это не так: утиная типизация даёт бо́льшую свободу.                                                 | Помните, что важна не иерархия, а наличие методов.                                                                         |
| Создают слишком абстрактный базовый класс с пустыми методами        | Это может привести к тому, что в наследниках забудут переопределить метод, и вызов приведёт к ошибке.        | Используйте `raise NotImplementedError` в родительском методе, чтобы явно указать, что его необходимо переопределить.      |

---

### Краткий итог

- **Полиморфизм** — способность объектов разных классов отвечать на один и тот же вызов метода своим собственным образом.
- Основной способ реализации — **переопределение методов** в дочерних классах.
- В Python полиморфизм выходит за рамки наследования благодаря **утиной типизации**: важны методы, а не типы.
- Полиморфизм делает код гибким, сокращает дублирование и упрощает расширение.
- Используйте полиморфизм для написания универсальных функций, работающих с широким спектром объектов.

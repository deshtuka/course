# Тема 5. Логирование

## Введение

Логирование — это основа отладки и мониторинга в автотестах. Представьте: ваш тест упал, и в консоли только «AssertionError». Что пошло не так? Какой запрос был отправлен? Что пришло в ответ? Без логов вы теряете часы на воспроизведение проблемы.

В контексте автоматизации тестирования логирование решает три главные задачи:

1. **Диагностика** — понимать, что происходило во время выполнения теста: какие данные отправлялись, какие ответы приходили, сколько времени занял каждый шаг.
2. **Трассировка** — видеть поток выполнения в многошаговых сценариях (например, создание заказа → оплата → проверка статуса).
3. **Аудит** — сохранять историю выполнения для анализа стабильности тестового стенда.

В Python есть встроенный модуль `logging`, но он громоздок в настройке. Альтернатива — **Loguru** — библиотека, которая делает логирование простым, красивым и удобным. В этой теме мы разберём, как базовый инструмент, так и Loguru, а также определим, почему последний лучше для автотестировщика, и как использовать его на полную мощность.

---

## Сравнение `logging` и `Loguru`

Стандартный модуль `logging` существует с первых версий Python. Он надёжен и гибок, но его настройка — это головная боль. Чтобы выводить цветной лог с временем, уровнем и именем модуля, нужно написать 10–15 строк кода (создать форматтер, хендлеры, настроить корневой логгер).

**Loguru** решает эти проблемы «из коробки»:

| Критерий                    | `logging`                                                             | `Loguru`                                                           |
|:----------------------------|:----------------------------------------------------------------------|:-------------------------------------------------------------------|
| **Настройка по умолчанию**  | Только вывод в консоль с минимальным форматом                         | Уже есть цветной вывод с временем, уровнем, именем файла и строкой |
| **Добавление обработчиков** | Требует создания `Handler`, `Formatter` и привязки к логгеру          | Одна строка: `logger.add("file.log")`                              |
| **Ротация файлов**          | Нужно подключать `RotatingFileHandler` или `TimedRotatingFileHandler` | Встроена: `logger.add("file.log", rotation="1 day")`               |
| **Контекстное логирование** | Через `LoggerAdapter` — сложно и многословно                          | Просто: `logger.bind(user_id=123).info("Запрос отправлен")`        |
| **Исключения**              | `logger.exception()` фиксирует traceback                              | `logger.exception()` + автоматическое добавление стека             |
| **Асинхронность**           | Не поддерживается                                                     | Поддерживается асинхронная запись (параметр `enqueue=True`)        |
| **Цвета**                   | Только через сторонние библиотеки (colorlog)                          | Цвета встроены и настраиваются                                     |
| **Гибкость**                | Высокая, но сложная                                                   | Достаточная для 99% задач, простая                                 |

**Вывод:** Loguru не пытается заменить `logging` во всех сценариях, но для автотестов он идеален — минимум кода, максимум пользы.

> Официальная документация.
> - Logging: https://docs.python.org/3/library/logging.html
> - Loguru: https://loguru.readthedocs.io/en/stable/index.html

## Установка

Установите Loguru:

```
pip install loguru
```

Первое использование — просто импорт и вызов:

```python
from loguru import logger

logger.info("Тест запущен")
logger.debug("Отладочное сообщение")
logger.warning("Внимание!")
logger.error("Ошибка!")
logger.critical("Критическая ошибка!")
```

В консоли вы увидите цветной вывод с временем, уровнем, именем файла, номером строки и самим сообщением.

## Уровни логирования

Уровни логирования (по возрастанию серьёзности):

- **TRACE** (5) — мельчайшие детали
- **DEBUG** (10) — отладочная информация
- **INFO** (20) — основные события
- **SUCCESS** (25) — успешное завершение операции
- **WARNING** (30) — предупреждения
- **ERROR** (40) — ошибки
- **CRITICAL** (50) — фатальные ошибки

Установка минимального уровня для вывода:

```python
logger.add(sys.stderr, level="INFO")   # показывать INFO и выше
```

В автотестах обычно используют `INFO` для основного хода выполнения, `DEBUG` для деталей запросов/ответов, `ERROR` для падений.

---

## Добавление обработчиков: консоль, файл, ротация

В Loguru все настройки выполняются через метод `add()`. Вы можете добавлять несколько обработчиков одновременно.

**Вывод в файл:**

```python
logger.add("logs/test.log")
```

**С ротацией по размеру или времени:**

```python
# Ротация при достижении 10 МБ
logger.add("logs/test.log", rotation="10 MB")

# Ежедневная ротация в полночь
logger.add("logs/test_{time:YYYY-MM-DD}.log", rotation="1 day")

# Ротация по времени с добавлением даты в имя файла
logger.add("logs/test_{time}.log", rotation="1 week")
```

**Ограничение количества файлов:**

```python
logger.add("logs/test.log", retention="30 days")   # хранить логи за 30 дней
```

**Сжатие старых логов:**

```python
logger.add("logs/test.log", compression="zip")
```

**Асинхронная запись (не блокирует основной поток):**

```python
logger.add("logs/test.log", enqueue=True)
```

## Форматирование вывода

Формат по умолчанию удовлетворяет основные потребности, но вы можете его кастомизировать:

```python
logger.add(
    sys.stdout,
    format="{time:YYYY-MM-DD HH:mm:ss} | {level} | {name}:{function}:{line} | {message}",
    colorize=True
)
```

Доступные переменные:

- `{time}` — время
- `{level}` — уровень логирования
- `{name}` — имя модуля
- `{function}` — имя функции
- `{line}` — номер строки
- `{message}` — сообщение
- `{exception}` — информация об исключении (если есть)
- `{extra}` — пользовательские атрибуты (см. ниже)

## Контекстное логирование: `bind()` и `contextualize()`

**Основная фича Loguru** — возможность добавлять к любому сообщению произвольные атрибуты, которые будут автоматически подставляться в формат.

**Статическое связывание (на уровне логгера):**

```python
logger.add(sys.stdout, format="{extra[user_id]} | {message}")   # добавить поле extra

# Теперь привязываем пользователя
log = logger.bind(user_id=123)
log.info("Пользователь авторизован")
log.info("Пользователь отправил запрос")
```

Все сообщения от `log` будут содержать `user_id=123`. Это удобно для отслеживания действий конкретного пользователя в тесте.

**Динамический контекст через `contextualize()`:**

Если у вас есть блок кода, в котором нужно временно добавить атрибут для всех логов внутри этого блока:

```python
with logger.contextualize(test_id="test_001"):
    logger.info("Начало теста")   # будет содержать test_id
    # ... много кода ...
    logger.info("Конец теста")
```

Всё, что внутри `with`, будет автоматически дополнено полем `test_id`. Это идеально для логирования в рамках одного тест-кейса.

## Логирование исключений и стектрейсов

Loguru автоматически добавляет стектрейс в лог при использовании `logger.exception()`:

```python
try:
    1 / 0
except ZeroDivisionError:
    logger.exception("Деление на ноль")
```

В выводе будет полный traceback с цветовой подсветкой.

Также можно использовать декоратор `@logger.catch` для перехвата исключений в функции:

```python
@logger.catch
def risky_function():
    return 1 / 0

risky_function()   # ошибка будет залогирована, но выполнение продолжится (по умолчанию)
```

Это удобно для диагностики проблем без остановки всего тестового прогона.

## Интеграция с HTTPX: логируем каждый запрос

В предыдущей теме мы говорили об event hooks в HTTPX. Теперь объединим их с Loguru, чтобы логировать все запросы и ответы.

```python
import httpx
from loguru import logger

def log_request(request):
    logger.info(f"→ {request.method} {request.url}")

def log_response(response):
    request = response.request
    logger.info(f"← {request.method} {request.url} → {response.status_code}")
    if response.status_code >= 400:
        logger.error(f"Ошибка: {response.text[:200]}")

with httpx.Client(
    event_hooks={
        'request': [log_request],
        'response': [log_response]
    }
) as client:
    client.get("https://api.example.com/users")
```

Можно добавить ещё и логирование тела запроса (только для `json` или `data`), но не забывайте о чувствительных данных — пароли, токены, персональные данные лучше скрывать или маскировать.

## Интеграция с Pydantic: логируем ошибки валидации

При создании моделей Pydantic часто возникают ошибки валидации. Логируйте их детально:

```python
from pydantic import BaseModel, ValidationError
from loguru import logger

class User(BaseModel):
    id: int
    name: str

def parse_user(data):
    try:
        return User(**data)
    except ValidationError as e:
        logger.error(f"Ошибка валидации: {e.errors()}")
        logger.debug(f"Входные данные: {data}")
        return None
```

## Логирование в автотестах: практические рекомендации

1. **Один логгер на весь проект** — импортируйте глобальный `logger` из Loguru, настраивайте его один раз при старте тестов (например в `conftest.py`).

2. **Уровни логирования:**
   - `DEBUG` — всё, что касается запросов, ответов, промежуточных данных.
   - `INFO` — ключевые шаги теста (создание сущности, переход на страницу, проверка).
   - `WARNING` — неожиданные, но не фатальные ситуации (например, пустой список).
   - `ERROR` — упавшие проверки, исключения.

3. **Сохраняйте логи в отдельную папку** с ротацией по дням, чтобы не засорять диск.

4. **Добавляйте в логи время выполнения шагов** — это помогает выявить медленные операции.

5. **Маскируйте конфиденциальные данные** — используйте фильтры или кастомную обработку сообщений.

---

## Распространенные ошибки

1. **Чрезмерное логирование.** Логирование каждого цикла в цикле из 10 000 итераций сделает лог огромным и бесполезным. Используйте `DEBUG` для деталей и `INFO` только для важных этапов.
2. **Игнорирование уровней.** Вывод всех сообщений как `logger.info` лишает смысла фильтрацию. Используйте правильные уровни.
3. **Забываете настроить обработчики для файлов.** Без этого логи видны только в консоли, и при падении теста на CI вы не сможете их проанализировать.
4. **Не используете `bind()` и `contextualize()`.** Вместо этого вручную добавляете ID в каждое сообщение — это избыточно и грязно.
5. **Логирование конфиденциальных данных.** Пароли, токены, номера карт не должны попадать в логи. Либо маскируйте их, либо исключайте из логов вообще.
6. **Смешивание логирования и print.** `print` не имеет уровней, не управляется, не сохраняется в файлы. Используйте только `logger`.
7. **Слишком частое открытие/закрытие файлов.** Loguru держит файловые дескрипторы открытыми, это нормально. Не создавайте новый обработчик для каждого теста — настройте один раз.
8. **Отсутствие ротации.** Со временем логи могут занять гигабайты. Всегда настраивайте `rotation`.

---

## Краткий итог

- **Loguru** — это современная, простая и мощная библиотека для логирования, идеально подходящая для автотестов.
- Она избавляет от сложной настройки стандартного `logging`, предоставляя красивый цветной вывод, гибкую ротацию файлов, контекстное логирование и удобный захват исключений.
- **Ключевые приёмы:** `logger.add()` для обработчиков, `logger.bind()` и `contextualize()` для контекста, `logger.exception()` для стектрейсов, интеграция с HTTPX через event hooks.
- В автотестах логирование помогает быстро локализовать проблему, отслеживать поток выполнения и сохранять историю для анализа.

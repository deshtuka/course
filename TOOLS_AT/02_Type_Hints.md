# Тема 2. Аннотации типов (Type Hints)

## Зачем тестировщику указывать типы?

Автотесты — это тоже код. И чем он понятнее, тем проще его поддерживать. Аннотации типов (или type hints) превращают ваш код в самодокументируемый: глядя на сигнатуру функции, вы сразу видите, **что** она принимает и **что** возвращает.

В связке с современными IDE (PyCharm, VS Code, GigaIDE) аннотации дают:
- автодополнение (подсказки методов и атрибутов);
- раннее обнаружение ошибок (если вы передаёте строку туда, где ожидается число, редактор подсветит это ещё до запуска);
- улучшенную читаемость для коллег и для самого себя через месяц.

**Важно:** аннотации **не влияют** на выполнение программы — Python не проверяет типы во время работы. Это исключительно подсказка для разработчика и инструментов статического анализа (mypy, pylint, ruff).

## Базовый синтаксис

### Аннотация переменных
Для аннотации переменных ставится двоеточие `:` после имени переменной, а затем указывается тип:

```python
# Аннотация базовых типов
name: str = "Максим"
age: int = 33
height: float = 1.91
is_developer: bool = True
```

### Аннотация функций

В функциях мы можем указать типы для передаваемых аргументов и тип возвращаемого значения (используя стрелку `->`):

```python
def greet(name: str, age: int) -> str:
    return f"Привет, {name}! Тебе {age} лет."

message = greet("Иван", 14)
print(message)      # Привет, Иван! Тебе 14 лет.
```

В этом примере:

- `name: str` — ожидается строка
- `age: int` — ожидается целое число
- `-> str` — функция обязуется вернуть строку

> Примечание: если функция ничего не возвращает, мы используем тип возвращаемого значения `None`, например `-> None`.

## Типизация коллекций: списки, словари и кортежи

Чтобы указать, из каких элементов состоит список или словарь, используйте синтаксис с квадратными скобками.

```python
def get_user_names(users: list[dict]) -> list[str]:
    """Принимает список словарей, возвращает список имён."""
    return [user["name"] for user in users]
```

Если словарь имеет строгую структуру, то можно уточнить:

```python
def update_user(data: dict[str, int]) -> dict[str, str]:
    # data содержит ключи-строки и значения-числа
    return {k: str(v) for k, v in data.items()}
```

Для кортежей с фиксированным количеством элементов:

```python
def parse_coordinates() -> tuple[float, float]:
    return (55.75, 37.61)   # широта, долгота
```

## Модуль typing

Для более сложных сценариев используется встроенный модуль `typing`

### Optional (Опциональное значение)

В реальных API часто приходит поле, которого может не быть, или оно может быть `None`. Для этого используем `Optional` (означает «либо указанный тип, либо None»).

```python
from typing import Optional

def get_user_email(user_id: int) -> Optional[str]:
    # Если email не найден, возвращаем None
    emails = {1: "anna@mail.com", 2: "alex@mail.com"}
    return emails.get(user_id)   # может вернуть None
```

### Union (Объединение типов)

Альтернативный вариант `Optional` это использование `Union`, если нужно разрешить указать несколько типов:

```python
from typing import Union

def parse_response(status: Union[int, str]) -> str:
    # можно передать и число, и строку
    return f"Статус: {status}"
```

Начиная с **Python 3.10** можно использовать более лаконичный синтаксис через `|`:

```python
def parse_response(status: int | str) -> str:
    return f"Статус: {status}"

def get_user_email(user_id: int) -> str | None:
    ...
```

> В современных проектах предпочтительнее использовать `|` — это читается легче и не требуется подключать библиотеку

## Аннотации для более сложных структур

В тестах API мы часто работаем с вложенными JSON. Если вложенность глубокая, можно использовать `dict` с уточнёнными типами вложенных значений.

```python
def validate_payment(data: dict[str, dict[str, int | float]]) -> bool:
    # data = {"order": {"amount": 100.50, "tax": 10}}
    total = data.get("order", {}).get("amount", 0)
    return total > 0
```

Если структура становится сложной, на помощь приходит **Pydantic** (о нем поговорим позднее), но для простых случаев аннотаций достаточно.

## Аннотации в методах классов

В классах, которые описывают модели данных или утилиты, аннотации так же полезны:

```python
class TestUser:
    def __init__(self, name: str, age: int) -> None:
        self.name = name
        self.age = age

    def get_info(self) -> str:
        return f"{self.name}, {self.age} лет"
```

Возврат `None` у конструктора/инициализатора — это стандартная практика.

---

## Из практики

Аннотации должны упрощать, а не усложнять код. Не нужно типизировать каждую переменную внутри функции — это перебор. Достаточно описать параметры и возвращаемые значения.

**Плохо:**

```python
x: int = 5
y: str = "hello"
```

**Хорошо:**

```python
def make_request(url: str, timeout: int = 30) -> httpx.Response:
    ...
```

## Краткий итог

Аннотации типов — это простой, но мощный инструмент, который делает ваши тесты надёжнее и понятнее. Используйте их всегда, где это уместно, и ваш код скажет «спасибо».

**1. Для чего используются аннотации типов в Python?**

А) Для принудительной проверки типов во время выполнения.  
Б) Для указания ожидаемых типов переменных, аргументов и возвращаемых значений с целью улучшения читаемости и поддержки статическими анализаторами.  
В) Для автоматического преобразования типов во время выполнения.  
Г) Для ускорения работы программы.

**Правильный ответ:** Б

**2. Какой синтаксис используется для аннотации типа переменной `x` как целого числа?**

А) `x = int`
Б) `x: int`
В) `x = int()`
Г) `x(int)`

**Правильный ответ:** Б

А) `def func(s: str) -> [int]:`  
Б) `def func(s: str) -> List[int]`
В) `def func(s): -> list[int]`  
Г) `def func(s: str) -> list[int]:`

**Правильный ответ:** Г

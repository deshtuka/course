# Тема 1. Введение в инструменты

В автотестах важны не только сами проверки, но и то, **как** они написаны: насколько код читаемый, как быстро находится ошибка, удобно ли сопровождать тесты через полгода. Именно поэтому мы разберём набор инструментов, которые делают тесты понятнее, надёжнее и удобнее для команды.

## Что будем использовать?

### Аннотации типов
Аннотации типов показывают, какие значения ожидает функция или объект. В учебных и рабочих проектах это помогает сразу понимать интерфейс кода, снижает количество ошибок и улучшает автодополнение в IDE.

Пример:
```python
def make_user_id(name: str) -> int:
    return len(name)
```

Здесь сразу видно: функция принимает строку и возвращает число. Для тестов это полезно везде — от вспомогательных функций до API-клиентов и моделей данных.

### Pydantic
Pydantic нужен для описания и проверки данных через классы-модели. В контексте автотестов это особенно удобно для request- и response-моделей: можно заранее описать структуру ответа и проверить, что API возвращает именно то, что ожидается.

Пример:
```python
from pydantic import BaseModel

class User(BaseModel):
    id: int
    name: str
```

Если данные не соответствуют модели, Pydantic поднимет исключение `ValidationError`. Это удобно в автотестах: ошибка становится явной и понятной, а не всплывает позже в виде странного `KeyError` или `TypeError`.

### Httpx
Httpx — это HTTP-клиент, который удобно использовать для отправки запросов в API. У нас он будет основным инструментом для общения с сервисом: через него мы будем делать `GET`, `POST`, `PUT`, `DELETE`, передавать `params`, `json`, `headers` и проверять ответы.

Практически это означает, что тесты смогут работать не только на уровне “проверить функцию”, но и на уровне реального взаимодействия с сервисом — а это уже полноценный API-автотест.

### Logging
Логирование нужно для того, чтобы понимать, что именно делал тест до падения: какой запрос отправил, какой ответ получил, на каком шаге остановился. Без логов отладка автотестов часто превращается в догадки.

Разберем современный и удобный вариант — Loguru, но важно понимать и сам принцип: логирование должно помогать быстро разбирать ошибки и не мешать чтению кода.

## Как эти инструменты связаны?

Упрощённо рабочий сценарий в автотестах выглядит так:

1. **Аннотации типов** помогают описать функции и данные.
2. **Pydantic** проверяет структуру данных и превращает их в удобные модели.
3. **Httpx** отправляет запросы в API.
4. **Logging** сохраняет контекст выполнения и помогает отлаживать падения.

Именно вместе эти инструменты дают аккуратный и поддерживаемый тестовый код, а не набор разрозненных запросов и проверок.
